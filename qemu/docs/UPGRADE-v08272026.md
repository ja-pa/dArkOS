# G350 QEMU upgrade to v08272026

The target branch starts at upstream `9faeb5883ea6bb567d802ee8ca7333b6ce6c8854`.
The fourteen commits in `4518be7..5ae79c1` were cherry-picked in order. The only
textual conflict was `.gitignore`; both upstream and QEMU rules were retained.
Follow-up commits adapt the port to the new image.

## Verified input

The supplied two-volume archive passed `7z t`. Its image is
`dArkOS_G350_trixie_09022026.img`, 8,301,576,192 bytes, timestamp September 2,
2026 20:59:05 UTC. SHA256 values are recorded in `locks/g350-v08272026.json`.
They were calculated locally from the supplied inputs. The image stays read-only.

The new DOS partition identity is `0x32d47912`, replacing `0x9aef4565`; ROOTFS is
partition 2, Btrfs, and EASYROMS is partition 3. Partition offsets and sizes are
otherwise compatible with the existing G350 growth procedure. Growth now checks
the overlay against the actual inspected base layout and preserves its identity.

source mapping, not proof of which commit produced the original binaries.

and ROM layout are retained, subject to runtime validation.

The new-image service audit also found enabled `351mp`, `batt_led`, `logo` and
`wifi_importer` units. The QEMU profile masks these board LED/brightness/volume,
battery, framebuffer logo and physical Wi-Fi import hooks in addition to the
existing firstboot, original frontend and hardware audio hooks.

## Reproduction and isolation

Use `WORK_DIR=$HOME/darkos-g350-qemu-v08272026` and the new default lock.
`ARCHIVE_DIR=/mnt/c/Users/japa1/Documents/ChatGPT/darkos_qemu/images` contains
both supplied volumes. Run the existing `make qemu-*` stages as documented.
Shell tools, diagnostics and the exporter share release selection. To select
the old image, set `RELEASE_LOCK=$PWD/qemu/locks/g350-v01302026.json` and a
separate old `WORK_DIR` explicitly. No old runtime disk or stage receipt is reused.

Import, initial disk preparation, component and kernel builds check free space;
export also checks the Windows backing drive. Insufficient space is an error,
not authorization to delete old environments. The standalone package uses the
new image date in its name and includes its source lock and provenance.

The runtime writes a root-only NetworkManager keyfile for `QEMU VirtIO Ethernet`
with DHCP and a higher autoconnect priority than automatically generated profiles.
Both cold-boot acceptance passes check that this profile is actually active.
The first validation boot reached multi-user and started SSH but did not answer
forwarded connections; a diagnostic reboot worked. Explicit provisioning removes
dependence on first-boot automatic profile creation; repeat boot tests are required.

The SDK linker search order now resolves private SDL/Mesa transitive dependencies
before vendor `/usr/lib` copies. A clean build of the SDK demo exposed vendor
`libgbm.so.1` selection and unresolved GBM symbols; the private-first link order
addresses this independently of the guest's already isolated runtime libraries.
Repeated `sdk.sh prepare` also refreshes SDK launchers/toolchain metadata when
the existing sysroot remains valid.
